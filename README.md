# Switchboard

Локальний оркестратор для двох кодинг-агентів (Claude Code і Antigravity `agy`): показує ліміти, розподіляє задачі й передає їх іншому агентові, коли в першого закінчується ліміт. Мерж у `main` і деплой робиш лише ти.

> Статус: **Етап 3 з 5** (ліміти, дешборд, запуск однієї задачі одним агентом). Повний README з усіма командами буде наприкінці.
> Результати розвідки: [docs/recon.md](docs/recon.md).

## Встановлення

Потрібні Node.js 20+ і pnpm (`corepack enable`), встановлені й залогінені `claude` та `agy`.

```bash
git clone https://github.com/olexlebid/switchboard
cd switchboard
pnpm install
pnpm sb status
```

## Команди (зараз)

| Команда | Що робить |
|---|---|
| `pnpm sb status` | Читає свіжі ліміти (`claude -p "/usage"`, `agy -p "/quota"`), зберігає в `~/.switchboard/state.json` і друкує статуси |
| `pnpm sb status --cached` | Показує останній збережений знімок без запитів до CLI |
| `pnpm sb status --json` | Те саме у JSON (для дешборду) |
| `pnpm sb dashboard` | Дешборд на **http://127.0.0.1:4321** (dev-режим з hot reload, зручно перефарбовувати) |
| `pnpm sb dashboard --prod [--port N]` | Збирає й запускає окремий сервер без hot reload |
| `pnpm sb init <проєкт>` | Створює `RULES.md`, `DESIGN.md`, `CLAUDE.md` (`@RULES.md`), `AGENTS.md`, `.sb/tasks/`; існуючих файлів не перезаписує |
| `pnpm sb run "<задача>" --project <папка> [--type section] [--agent claude\|agy] [--priority high] [--figma <url>] [--timeout <хв>]` | Запускає задачу в гілці `sb/<id>`, пише лог, комітить результат |
| `pnpm sb queue` | Список задач зі статусами |
| `pnpm sb hook install [--dry-run]` | Необов'язково: підключає statusLine-хук у `~/.claude/settings.json` (спершу робить бекап, існуючий statusLine обгортає) |
| `pnpm sb hook uninstall` | Повертає `statusLine` до стану до встановлення |
| `pnpm test` / `pnpm typecheck` | Тести й перевірка типів |

### Як відкотити зміни в `~/.claude/settings.json`

`sb hook install` кладе повну копію файлу поруч: `~/.claude/settings.json.sb-backup-<час>`. Відкат: `pnpm sb hook uninstall` (повертає лише ключ `statusLine`) або просто скопіюй бекап назад.
Хук корисний, лише якщо твоя версія Claude Code віддає `rate_limits` у statusLine JSON (у 2.1.286 цього поля немає), тому для статусу він не обов'язковий.

## Статуси

| Статус | Умова (пороги в `switchboard.config.yaml`) |
|---|---|
| доступно | усі вікна нижче `low` (60%) |
| мало | будь-яке вікно ≥ `low` |
| резерв | тижневе ≥ `weeklyReserve` (75%) |
| вичерпано | вікно ≥ `exhausted` (90%) або свіжий реактивний сигнал про ліміт |
| невідомо | даних немає або вони старші за `limits.staleAfterMin` (30 хв) |

Вікно, час скидання якого вже минув, вважається порожнім (0%). Для `agy` відсотки беруться з групи моделей із найменшим використанням (агент доступний, поки є хоча б одна група з запасом); вибір моделі з потрібної групи зробить роутер на Етапі 4.

## Дані й приватність

Стан лежить у `~/.switchboard/` (права `0600`, поза git). Email показується замаскованим (`ole…@gmail.com`), токени в логи не потрапляють (`packages/core/mask.ts`).

## Дешборд

Astro SSR (`apps/dashboard`), слухає **лише `127.0.0.1`**, у Netlify не деплоїться.

- Шапка: чипи `N доступно · N мало · N резерв · N вичерпано · N невідомо`, час оновлення, кнопка «Оновити».
- Картка агента: статус (завжди текстом, не лише кольором), смуги «5 год» і «Тиждень» із `aria-valuenow`, відлік `↻ 3 г 36 хв`, для `agy` ще групи моделей, нижній рядок з кількістю моделей, джерелом і віком даних. Дані старші за 30 хв напівпрозорі з позначкою «застаріло»; вичерпаний агент має пунктирну рамку.
- Ручні картки (Gemini-чат, Stitch): кнопки «Доступно» / «Вичерпано». У роутингу участі не беруть; список у `dashboard.manualCards` конфігу (`[]` ховає їх).
- Сторінка кожні 30 с запитує `/fragment` (готовий серверний HTML) і підміняє `#dashboard`; відліки й «2 хв тому» перераховуються в браузері кожні 15 с. Сервер перечитує ліміти з CLI не частіше ніж раз на `dashboard.refreshTtlSec` (60 с); кнопка «Оновити» читає одразу.
- `/api/status` віддає те саме у JSON; `POST /api/refresh` і `POST /api/manual` змінюють стан. Усі запити з чужим `Host` (DNS-rebinding) або чужим `Origin` дістають 403.

### Як перефарбувати

Усі кольори, радіуси й відступи — це CSS-змінні на початку `apps/dashboard/src/styles/global.css`. Розмітка карток: `apps/dashboard/src/components/`.

## Запуск задачі (`sb run`)

1. Перевіряє, що папка є git-репозиторієм і **робоче дерево чисте** (інакше зупиняється з кодом 3 і нічого не чіпає).
2. Створює гілку `sb/<id>` від поточної, пише `.sb/tasks/<id>.md` (тип, пріоритет, Figma, критерії готовності).
3. Запускає агента без інтерактивності (`claude -p …` або `agy -p …`) у корені проєкту. Дозволи беруться з секції `permissions` у `switchboard.config.yaml`; повного обходу підтверджень немає. Тайм-аут за замовчуванням 20 хв, при перевищенні вбивається вся група процесів.
4. Лог іде в `~/.switchboard/runs/<run-id>.log` з маскуванням токенів і ключів; сам промпт у лог не пишеться.
5. Результат оцінюється **не за кодом виходу**, а за відповіддю агента: заблоковані дії (`permission_denials` / `denied_actions`) дають статус «заблоковано», `is_error` або тайм-аут дають «помилка».
6. Успіх: коміт `feat(sb): … [<id>]`. Інакше: чекпойнт `wip(sb): checkpoint <id> from <agent>` (щоб не втратити зроблене). Порожніх комітів немає.
7. Проєкт повертається на гілку, з якої стартували. `main` не змінюється ніколи; push гілки лише з `git.pushBranches: true`, без `--force`; мерж і деплой робиш ти.

Коди виходу: `0` готово, `1` помилка, `2` неправильні аргументи, `3` брудне дерево, `4` заблоковано.

Типи задач і порядок агентів задаються в `routing` конфігу. Щоб додати тип, допиши рядок (`landing: [claude, agy]`) і, за бажання, критерії готовності для нього в `DONE_CRITERIA` у `packages/core/tasks.ts`.

`sb run` поки що бере першого агента зі списку для типу задачі (або `--agent`); вибір за статусами лімітів і автоматична передача іншому агентові з'являться на Етапі 4.
