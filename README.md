# Switchboard

Локальний оркестратор для двох кодинг-агентів — **Claude Code** (`claude`) і **Antigravity** (`agy`). Він:

- показує залишок лімітів обох підписок (5-годинне і тижневе вікна);
- розподіляє задачі між агентами за матрицею `routing` і поточними лімітами;
- запускає агента без інтерактивності в окремій гілці `sb/<id>`, зберігає роботу комітами;
- коли в одного агента закінчується ліміт, робить чекпойнт і **передає задачу іншому**;
- має **чат** з агентом (з правом редагувати файли) і **вкладення** (скріншоти, PDF, документи, відео…).

Мерж у `main` і деплой робиш **лише ти**: Switchboard цього не робить ніколи.

> Результати розвідки по CLI: [docs/recon.md](docs/recon.md). Правила для Claude в цьому репо: [CLAUDE.md](CLAUDE.md).

## Встановлення

Потрібно: **Node.js 20+**, pnpm (`corepack enable`), встановлені й залогінені `claude` та `agy` (один акаунт на провайдера, підписка, не API-ключ). Для відео-вкладень додатково `ffmpeg` (необов'язково).

```bash
git clone https://github.com/olexlebid/switchboard
cd switchboard
pnpm install
pnpm sb status          # перевірка: має показати ліміти обох агентів
```

Дані зберігаються в `~/.switchboard/` (права `0600`, поза git): `state.json` (стан, задачі, чати), `runs/` (логи запусків), `backups/` (бекапи налаштувань `agy`).

## Швидкий старт

```bash
pnpm sb dashboard                       # дашборд на http://127.0.0.1:4321
pnpm sb project add ~/projects/amaro    # дозволити проєкт для запуску з дашборду
pnpm sb init ~/projects/amaro           # одноразово: файли правил для агентів
git -C ~/projects/amaro add -A && git -C ~/projects/amaro commit -m "chore: add Switchboard files"
```

Далі все можна робити з дашборду: обрати проєкт у шапці, писати в чат або запускати задачі.

## Дашборд

`http://127.0.0.1:4321`, слухає **лише `127.0.0.1`**, у Netlify не деплоїться. Побудований **виключно на shadcn/ui** (React-острів Astro, Tailwind v4); світла/темна/системна тема перемикається в шапці.

| Зона | Що там |
|---|---|
| Шапка | зведення статусів, вибір **проєкту**, час оновлення, «Оновити», тема |
| Ліворуч | картки **Claude Code** і **Antigravity** (одна під одною): статус текстом, смуги «5 год» і «Тиждень», відлік до скидання, групи моделей |
| Праворуч | **Чат** (висота дорівнює двом карткам ліворуч) |
| Під ними | «Ручні позначки» (Gemini-чат, Stitch: для сервісів без API, у роутингу не беруть участі) |
| Знизу | форма **«Нова задача»** і панель задач (вкладки: Виконується, Черга, Останні, Передачі) |

Дані приходять із `GET /api/state` (JSON): кожні 30 с, а поки йде задача чи відповідь у чаті, кожні 3 с. Сервер перечитує ліміти з CLI не частіше ніж раз на `dashboard.refreshTtlSec` (60 с); «Оновити» читає одразу. Відліки перераховуються в браузері.

Режими: `pnpm sb dashboard` (dev з hot reload) і `pnpm sb dashboard --prod [--port N]` (збірка і запуск).

## Задачі

Задача — довга робота на кшталт «зроби секцію за дизайном» у власній гілці.

**З дашборду:** форма «Нова задача» (текст, тип, пріоритет, Figma-посилання, файли) → «Запустити». Запускається окремий процес `sb run`, тож задача переживе перезапуск дашборду.

**З термінала:**

```bash
pnpm sb run "Зроби секцію Features за DESIGN.md" --project ~/projects/amaro --type section
```

Що відбувається:

1. Перевіряється, що папка — git-репозиторій і **робоче дерево чисте** (інакше код 3, нічого не чіпається).
2. Створюється гілка `sb/<id>` і файл `.sb/tasks/<id>.md` (тип, пріоритет, Figma, критерії готовності).
3. Роутер обирає агента (або `--agent` закріплює його); агент запускається без інтерактивності. Тайм-аут за замовчуванням 20 хв, при перевищенні вбивається вся група процесів.
4. Лог іде в `~/.switchboard/runs/<run-id>.log` з маскуванням токенів; сам промпт у лог не пишеться.
5. Результат оцінюється **за відповіддю агента**, а не за кодом виходу: заблоковані дії → «заблоковано», `is_error`/тайм-аут → «помилка». Враховується і `PROGRESS.md`: `Status: blocked` → «заблоковано», `Status: in-progress` → «не завершено».
6. Завершена задача: коміт `feat(sb): … [<id>]`; інакше чекпойнт `wip(sb): …`. Проєкт повертається на гілку, з якої стартували.

Коди виходу: `0` готово, `1` помилка, `2` неправильні аргументи, `3` брудне дерево, `4` заблоковано/чекає.

**Відповіді на питання агента.** Якщо агент у `PROGRESS.md` записав «Open questions», у вкладках «Черга/Останні» біля задачі є кнопка **«Продовжити»**: вона відкриває вікно з питаннями агента, полем для твоєї відповіді та можливістю додати файли. Відповідь потрапляє в промпт продовження. З термінала: `pnpm sb resume <id> --note "відповідь" [--attachments <папка>]`.

**Захищені файли.** Якщо після запуску змінено файл з `git.protectedPaths` (за замовчуванням `netlify.toml`, `.env*`), задача «заблокована», а гілка не пушиться.

**Якщо перервати `sb run`** (Ctrl+C, «Зупинити», `kill`): робота зберігається в коміті `wip(sb): checkpoint <id> interrupted`, задача стає «помилка (перервано)», проєкт лишається на гілці `sb/<id>` (повернутися: `git switch <твоя-гілка>`).

Одночасно в проєкті працює **одна** задача або одна відповідь чату (інакше 409).

## Чат

Чат — справа вгорі. Це постійна розмова з агентом, який **може редагувати файли проєкту**.

- **Гілка чату** `sb/c-<id>`; після кожної відповіді правки комітяться (`chat(sb): …`). `main` ніколи не змінюється, проєкт після відповіді повертається на твою гілку.
- **Перемикач «Авто / Claude / Antigravity».** «Авто» — роутер обирає агента за лімітами (спершу той, що відповідав востаннє, щоб зберегти його сесію; порядок задає `chat.order`). Якщо в агента закінчується ліміт, розмова автоматично передається іншому (до `handoff.maxHandoffs` разів на повідомлення). Обравши конкретного агента, ти відмовляєшся від передачі.
- **Безперервність.** Кожен агент веде власну сесію (`claude --resume`, `agy --conversation`). Коли відповідає інший агент, він отримує **транскрипт** останніх повідомлень і бачить правки на диску.
- **Історія.** Випадаючий список чатів проєкту та «Новий чат». Для кожного проєкту «активний» свій чат.
- **«Зупинити»** перериває відповідь; зміни зберігаються чекпойнтом.
- Якщо вільних агентів нема, чат переходить у стан «чекаю»; після скидання ліміту — кнопка «Спробувати знову».
- **Enter** надсилає, **Shift+Enter** — новий рядок, **Ctrl+V** вставляє скріншот із буфера.
- Відповіді показуються через безпечну підмножину markdown (спершу все екранується; дозволені лише `**жирний**`, `*курсив*`, `` `код` ``, блоки коду, списки, заголовки, `https`-посилання).

З термінала: `pnpm sb chat "що змінити" --project ~/projects/amaro [--agent claude|agy|auto] [--new]` — та сама розмова, що й у дашборді.

> Claude віддає відповідь одним блоком наприкінці, тож під час роботи показується «Агент працює · 1 хв» зі спінером, а не потік тексту.

## Вкладення

Файли можна додати до **задачі**, до **повідомлення чату** і до відповіді при **«Продовжити»**: кнопкою-скріпкою, перетягуванням або вставкою скріншота (Ctrl+V).

| Тип | Що отримує агент |
|---|---|
| `jpg jpeg png gif webp` | читається напряму |
| `avif tif tiff bmp` | конвертується в `png` (sharp) |
| `pdf` | читається напряму (якщо `agy` не відкриє PDF, він попросить скріншот) |
| `docx` | витягується текст (mammoth) |
| `xlsx` | перетворюється на CSV (до 2000 рядків на аркуш) |
| `mp4 mov webm m4v` | нарізаються кадри через `ffmpeg` (до 12); **звук не розпізнається**. Без `ffmpeg` файл лише зберігається |
| `mp3 wav m4a ogg aac` | лише зберігаються (транскрибації немає) |
| `txt md csv tsv json html css js ts astro yaml yml xml svg` | читаються як текст |

Ліміти: до 12 файлів, 100 МБ на файл (офісні — 25 МБ), 250 МБ разом. Назви очищаються, тип перевіряється за вмістом. Якщо `ffmpeg` не в `PATH`, вкажи його змінною `SB_FFMPEG`.

Файли лежать у `<проєкт>/.sb/attachments/<партія>/` і виключені через `.git/info/exclude`: робоче дерево лишається чистим, у git вони не потрапляють. Вміст вкладень для агента — довідковий матеріал, а не інструкції.

## Робота з існуючим проєктом

Приклад — сайт Amaro, де вже є `CLAUDE.md` і готовий дизайн у Figma. Тут **немає MCP**: працюємо зі скріншотами фреймів і текстовим описом.

1. **Одноразово:** `pnpm sb project add ~/projects/amaro` і `pnpm sb init ~/projects/amaro`.
   Оскільки в проєкті вже є `CLAUDE.md`, `sb init` не створює шаблони з TODO: він додає тонкі `RULES.md`, `DESIGN.md` і `AGENTS.md`, що **вказують на твій `CLAUDE.md`** (і на `src/styles/tokens.css`, якщо він є), щоб `agy` теж знав правила. У `RULES.md` сказано, що правила workflow Switchboard перекривають `CLAUDE.md` проєкту: агент не створює гілок, не комітить і не чекає на схвалення плану (у `CLAUDE.md` Amaro: «комітити напряму в `main`», «перед великою зміною чекати ок»). Закоміть ці файли.
2. **Нова сторінка за дизайном:** у «Нова задача» опиши, що зробити («Реалізуй сторінку Hochzeitstanz за скріншотами»), прикріпи скріншоти десктоп/мобайл (і PDF/docx із текстами), тип `section`, «Запустити».
3. **Дрібні правки й питання:** у чаті («поправ відступ у hero», «що не так із контрастом?»), зі скріншотами за потреби.
4. **Перегляд:** `git -C ~/projects/amaro diff main..sb/<id>`, далі мержиш сам.

## Усі команди

| Команда | Що робить |
|---|---|
| `pnpm sb status [--cached] [--json]` | Свіжі ліміти (`claude -p "/usage"`, `agy -p "/quota"`) і статуси |
| `pnpm sb dashboard [--prod] [--port N]` | Дашборд на `http://127.0.0.1:4321` |
| `pnpm sb init <проєкт>` | `RULES.md`, `DESIGN.md`, `AGENTS.md`, `.sb/`; для проєкту з власним `CLAUDE.md` — тонкі вказівники на нього. Існуючих файлів не перезаписує |
| `pnpm sb run "<задача>" --project <папка> [--type section] [--agent claude\|agy] [--priority high] [--figma <url>] [--timeout <хв>] [--reviews <id>] [--no-handoff] [--attachments <папка партії>]` | Запустити задачу в гілці `sb/<id>` |
| `pnpm sb resume <id> [--agent …] [--note "відповідь"] [--attachments <папка>] [--no-handoff]` | Продовжити задачу, що чекає, заблокована або впала |
| `pnpm sb chat "<повідомлення>" --project <папка> [--agent claude\|agy\|auto] [--new] [--attachments <папка>]` | Чат із терміналу |
| `pnpm sb queue [--run-due]` | Список задач, черга, передачі; `--run-due` продовжує задачі, чий ліміт уже скинувся |
| `pnpm sb unblock claude\|agy` | Зняти хибну позначку «ліміт вичерпано» |
| `pnpm sb project add\|remove\|list <папка>` | Проєкти, дозволені для дашборду (проєкти з `sb run` додаються самі) |
| `pnpm sb notify-test` | Перевірити системне сповіщення (macOS) |
| `pnpm sb hook install [--dry-run]` / `uninstall` | Необов'язковий statusLine-хук для Claude Code (див. [відкат](#як-відкотити-claudesettingsjson)) |
| `pnpm test` / `pnpm typecheck` | Тести (vitest) й перевірка типів |

Фонового планувальника немає: задачу з черги запускає `sb resume <id>`, `sb queue --run-due` або кнопка «Продовжити».

## Керування з іншого Claude Code (наприклад, з проєкту Amaro)

Локальний Claude Code, запущений у проєкті (Amaro), може керувати Switchboard **через CLI**. Дашборд для цього не потрібен і запускати його не треба.

**Як викликати з будь-якої теки.** Скрипт `bin/sb` працює з будь-якого поточного каталогу й сам знаходить `tsx` і конфіг:

```bash
/Users/mac/switchboard/bin/sb status --json      # ліміти обох агентів (JSON)
```

(Підстав свій шлях до теки `switchboard`. Зручно зробити alias: `alias sb=/Users/mac/switchboard/bin/sb`.)

**Що може робити агент:**

| Потрібно | Команда |
|---|---|
| Дізнатися ліміти | `sb status --json` |
| Спитати/попросити правку в чаті | `sb chat "…" --project <абсолютний шлях> [--agent claude\|agy\|auto]` |
| Запустити довгу задачу | `sb run "…" --project <абсолютний шлях> --type section [--attachments <папка>]` |
| Подивитися задачі, чергу, передачі | `sb queue` |
| Продовжити задачу з відповіддю на питання агента | `sb resume <id> --note "відповідь"` |
| Додати проєкт / файли правил | `sb project add <шлях>`, `sb init <шлях>` |

**Правила для такого агента (важливо):**

1. **Шляхи до проєктів — лише абсолютні** (у лапках, якщо є пробіли): `sb` рахує відносні шляхи від поточної теки.
2. **`sb run` і `sb chat` блокуються до кінця роботи** (до 20 хв). Довгу задачу запускай у фоні (`… > /tmp/sb.log 2>&1 &`) і стеж за нею через `sb queue`.
3. **Поки йде задача чи відповідь чату, проєкт стоїть на гілці `sb/…`. Не редагуй файли проєкту в цей час**: зміни змішаються з роботою агента. Перед стартом дерево має бути чистим (`git status`).
4. Результат — це гілка `sb/<id>` або `sb/c-<id>`: показуй `git diff main..sb/<id>` і **не мерж у `main`, не пуш і не деплой** без прямого прохання користувача.
5. Не читай і не виводь секрети (`.env`, токени); нічого не ставь у `~/.switchboard/` руками.

**HTTP API дашборду** (якщо він запущений на `127.0.0.1:4321`; корисно для скриптів, а для агента зручніший CLI):

| Запит | Що робить |
|---|---|
| `GET /api/state?project=<шлях>` | усе, що бачить дашборд: ліміти, задачі, чат проєкту |
| `GET /api/status` | лише ліміти |
| `POST /api/tasks` (multipart: `text`, `type`, `project`, `priority`, `figma`, `files`) | нова задача |
| `POST /api/task-action` (`op=resume\|stop`, `id`, `note`, `files`) | продовжити / зупинити задачу |
| `POST /api/chat` (`op=new\|send\|stop\|mode\|select\|retry`, `chat`, `project`, `text`, `mode`, `files`) | дії чату |
| `POST /api/refresh`, `POST /api/manual` | оновити ліміти, ручні позначки |

```bash
curl -s "http://127.0.0.1:4321/api/state" | head -c 600
curl -s -F op=send -F chat=<id чату> -F text="поправ відступ у hero" http://127.0.0.1:4321/api/chat
```

Запити з чужим `Host` або `Origin` дістають 403 (захист від DNS-rebinding); `curl` до `127.0.0.1` проходить.

**Готовий запит для Claude Code в Amaro** (встав у першому повідомленні):

> Прочитай `/Users/mac/switchboard/README.md`, розділ «Керування з іншого Claude Code», і `/Users/mac/switchboard/CLAUDE.md`. Далі працюй із Switchboard через `/Users/mac/switchboard/bin/sb` за описаними там правилами. Спершу виконай `sb status --json` і скажи, який агент зараз вільніший.

## Статуси і роутер

| Статус | Умова (пороги в `switchboard.config.yaml`) | Що бере |
|---|---|---|
| доступно | усі вікна нижче `low` (60%) | будь-які задачі |
| мало | будь-яке вікно ≥ `low` | лише короткі типи (`router.shortTypes`) |
| резерв | тижневе ≥ `weeklyReserve` (75%) | лише `--priority high` |
| вичерпано | вікно ≥ `exhausted` (90%) або свіжий сигнал про ліміт | нічого до скидання |
| невідомо | даних нема або вони старші за `limits.staleAfterMin` (30 хв) | бере, але спершу пробується агент із відомим статусом |

Вікно, час скидання якого минув, вважається порожнім. Для `agy` відсотки беруться з групи моделей із найменшим використанням. Для `review` рецензентом стає завжди **інший** агент, ніж автор коду (`--reviews <id задачі>`); коли вільних агентів нема, задача стає в чергу до найближчого скидання (+ системне сповіщення).

## Передача між агентами при ліміті

**Як визначається ліміт.** Запуск вважається «впертим у ліміт», лише якщо він **завершився невдало** і один із патернів `limitDetection.patterns` збігається з **останніми** `tailLines` рядками виводу (текст, скопійований із самої задачі, ігнорується), або свіжий зріз показує вікно 100%. Час скидання береться зі зрізу, інакше з тексту повідомлення, інакше +1 година. Агент отримує позначку «вичерпано» до цього часу (зняти: `sb unblock <агент>`). Тайм-аут і заблоковані дії лімітом не вважаються.

**Що відбувається:**

1. коміт `wip(sb): checkpoint <id> from <агент>`;
2. якщо агент не оновлював `PROGRESS.md`, дописується секція `Handoff` (змінені файли, останні ~40 рядків виводу без секретів, час, причина);
3. роутер обирає іншого агента, який отримує промпт продовження (`agy` без `git`: він читає секцію Handoff);
4. не більше `handoff.maxHandoffs` (2) передач; далі пауза зі статусом «чекає» і сповіщенням.

`--no-handoff` зупиняє задачу на першому ліміті. Побачиш нове повідомлення про ліміт — допиши регулярний вираз у `limitDetection.patterns` (регістр не важливий); справжнє повідомлення лежить у логу `~/.switchboard/runs/<id>.log`.

### Запуск через `agy`: тимчасові права

`agy` у headless бере дозволи лише з користувацького `~/.gemini/antigravity-cli/settings.json`. Тому на час запуску Switchboard робить бекап цього файлу (`~/.switchboard/backups/`, 5 останніх), додає правило `write_file(<шлях проєкту>/)` (запис лише всередині проєкту), а після запуску знімає **саме ці** правила (оригінал повертається побайтово). При збої, тайм-ауті, Ctrl+C чи `kill` теж знімає; після аварії наступний запуск дочищає сам. Два запуски `agy` одночасно відхиляються. **Shell для `agy` не вмикається** (його `deny` не зупиняє команди), тому git/pnpm-задачі віддавай Claude.

## Як додати новий тип задачі

1. У `switchboard.config.yaml` допиши рядок у `routing` (порядок = вподобання агентів):

   ```yaml
   routing:
     landing: [claude, agy]
   ```

2. Якщо тип короткий (бере навіть агент зі статусом «мало»), додай його в `router.shortTypes`.
3. За бажання додай критерії готовності типу в `DONE_CRITERIA` у `packages/core/tasks.ts` (вони потрапляють у `.sb/tasks/<id>.md`).
4. Для гарної назви у формі дашборду додай рядок у `TYPE_LABEL` у `apps/dashboard/src/components/app/TaskForm.tsx` (інакше покажеться id).

Тип з'являється в списку форми автоматично; конфіг читається при кожному запиті, перезапуск не потрібен.

## Конфігурація

Усе в `switchboard.config.yaml` (шлях можна змінити змінною `SB_CONFIG`, каталог даних — `SB_HOME`):

| Секція | Призначення |
|---|---|
| `agents` | команди `claude`/`agy`, headless-аргументи, команди для лімітів, шлях налаштувань `agy` |
| `thresholds` | пороги `low` / `exhausted` / `weeklyReserve` |
| `routing`, `router.shortTypes` | матриця «тип задачі → агенти» |
| `chat.order` | порядок агентів для чату в режимі «Авто» |
| `handoff`, `limitDetection` | передача при ліміті, патерни повідомлень про ліміт |
| `permissions` | усе, що агентам дозволено (повного обходу підтверджень немає) |
| `git` | `pushBranches` (за замовчуванням `false`), `protectedPaths` |
| `run.timeoutMin` | тайм-аут одного запуску агента |
| `dashboard` | `refreshTtlSec`, `projects`, `manualCards` |
| `notifications` | системні сповіщення (macOS) |

## Безпека

- Агенти працюють лише в гілках `sb/*`: без merge у `main`, деплою, `--force` і `reset --hard`; `netlify.toml` і `.env*` захищені (задача блокується, гілка не пушиться).
- Один акаунт на провайдера; використовуються лише документовані команди CLI.
- Токени й ключі маскуються в логах і транскриптах (`packages/core/mask.ts`); email показується замаскованим.
- Дашборд слухає лише `127.0.0.1`; запити з чужим `Host` (DNS-rebinding) або `Origin` дістають 403.
- Запуск із дашборду: проєкт лише зі списку дозволених (перевірка за реальним шляхом після `..` і symlink); аргументи йдуть масивом без shell, текст задачі після `--`; id задач і чатів перевіряються за шаблоном; «Зупинити» діє лише на процес `bin/sb.ts`.
- Вкладення: очищені імена, перевірка типу за вмістом, ліміти розміру, шлях не може вийти за `.sb/attachments`.
- Стан у `~/.switchboard/` має права `0600`; запис у `state.json` захищено міжпроцесним локом.

## Як відкотити `~/.claude/settings.json`

Хук `sb hook install` необов'язковий (у Claude Code 2.1.286 statusLine не віддає `rate_limits`, тож для статусу він не потрібен). Якщо ти його ставив:

- `sb hook install` кладе повну копію файлу поруч: `~/.claude/settings.json.sb-backup-<час>`;
- **відкат:** `pnpm sb hook uninstall` повертає лише ключ `statusLine` до стану до встановлення;
- або скопіюй бекап назад: `cp ~/.claude/settings.json.sb-backup-<час> ~/.claude/settings.json`.

Тимчасові правила `agy` знімаються самі; якщо щось лишилося після аварії, наступний запуск дочистить, а оригінал лежить у `~/.switchboard/backups/`.

## Розробка

```bash
pnpm install
pnpm typecheck                                  # tsc, ядро
pnpm test                                       # vitest, сценарії на фейковому агенті (test/fake-agent.mjs)
pnpm --filter @switchboard/dashboard build      # збірка дашборду
```

Структура:

- `bin/sb.ts` — CLI;
- `packages/core/` — ядро (ліміти, роутер, запуск, чат, вкладення, стан): звичайний TypeScript без UI;
- `apps/dashboard/` — Astro SSR + React-острів: `src/pages/api/*` (JSON-ендпоінти), `src/components/app/*` (екрани), `src/components/ui/*` (компоненти shadcn/ui).

**UI — лише shadcn/ui.** Новий елемент: `npx shadcn@latest add <компонент>` у `apps/dashboard`, далі використовуємо його як є; кольори, типографіка й відступи — токени теми з `src/styles/global.css`. Власного CSS і інших UI-бібліотек не додаємо (див. [CLAUDE.md](CLAUDE.md)). Тести ніколи не палять реальні ліміти: failover перевіряється лише на `test/fake-agent.mjs`.

## Усунення проблем

| Симптом | Що робити |
|---|---|
| «Робоче дерево не чисте» | Закоміть або відклади зміни в проєкті: Switchboard не чіпає твою незакомічену роботу |
| «У проєкті вже виконується задача або чат» | Дочекайся завершення або натисни «Зупинити» |
| Агент позначений «вичерпано» помилково | `pnpm sb unblock claude` (або `agy`) |
| Статус «невідомо» | `pnpm sb status` перечитає ліміти; перевір, що `claude`/`agy` залогінені |
| Задача «процес sb зник» | Після збою чи `kill -9`: «Продовжити» |
| Відео без кадрів | Встанови `ffmpeg` або вкажи шлях у `SB_FFMPEG` |
| Дашборд не відкривається | Він слухає лише `127.0.0.1:4321`; перевір порт (`--port`) і саме цю адресу |
