# Switchboard

Локальний оркестратор для двох кодинг-агентів (Claude Code і Antigravity `agy`): показує ліміти, розподіляє задачі й передає їх іншому агентові, коли в першого закінчується ліміт. Мерж у `main` і деплой робиш лише ти.

> Статус: **Етап 5 з 5** (ліміти, дешборд із панеллю задач, запуск задач, роутер і передача між агентами). Повний README з усіма командами буде наприкінці.
> Результати розвідки: [docs/recon.md](docs/recon.md).

## Встановлення

Потрібні Node.js 20+ і pnpm (`corepack enable`), встановлені й залогінені `claude` та `agy`.

```bash
git clone https://github.com/olexlebid/switchboard
cd switchboard
pnpm install
pnpm sb status
```

## Команди (зараз)

| Команда | Що робить |
|---|---|
| `pnpm sb status` | Читає свіжі ліміти (`claude -p "/usage"`, `agy -p "/quota"`), зберігає в `~/.switchboard/state.json` і друкує статуси |
| `pnpm sb status --cached` | Показує останній збережений знімок без запитів до CLI |
| `pnpm sb status --json` | Те саме у JSON (для дешборду) |
| `pnpm sb dashboard` | Дешборд на **http://127.0.0.1:4321** (dev-режим з hot reload, зручно перефарбовувати) |
| `pnpm sb dashboard --prod [--port N]` | Збирає й запускає окремий сервер без hot reload |
| `pnpm sb init <проєкт>` | Створює `RULES.md`, `DESIGN.md`, `CLAUDE.md` (`@RULES.md`), `AGENTS.md`, `.sb/tasks/`; існуючих файлів не перезаписує |
| `pnpm sb run "<задача>" --project <папка> [--type section] [--agent claude\|agy] [--priority high] [--figma <url>] [--timeout <хв>]` | Запускає задачу в гілці `sb/<id>`, пише лог, комітить результат |
| `pnpm sb queue [--run-due]` | Список задач зі статусами, чергою й історією передач; `--run-due` продовжує задачі, що чекали скидання ліміту й уже можуть іти |
| `pnpm sb resume <id> [--agent claude\|agy]` | Продовжити задачу, що чекає, заблокована або впала (лічильник передач починається знову) |
| `pnpm sb unblock claude\|agy` | Зняти позначку «ліміт вичерпано», якщо вона хибна |
| `pnpm sb project add\|remove\|list <папка>` | Проєкти, у яких дешборд може запускати задачі (проєкти з `sb run` додаються самі) |
| `pnpm sb notify-test` | Перевірити системне сповіщення (macOS) |
| `pnpm sb hook install [--dry-run]` | Необов'язково: підключає statusLine-хук у `~/.claude/settings.json` (спершу робить бекап, існуючий statusLine обгортає) |
| `pnpm sb hook uninstall` | Повертає `statusLine` до стану до встановлення |
| `pnpm test` / `pnpm typecheck` | Тести й перевірка типів |

### Як відкотити зміни в `~/.claude/settings.json`

`sb hook install` кладе повну копію файлу поруч: `~/.claude/settings.json.sb-backup-<час>`. Відкат: `pnpm sb hook uninstall` (повертає лише ключ `statusLine`) або просто скопіюй бекап назад.
Хук корисний, лише якщо твоя версія Claude Code віддає `rate_limits` у statusLine JSON (у 2.1.286 цього поля немає), тому для статусу він не обов'язковий.

## Статуси

| Статус | Умова (пороги в `switchboard.config.yaml`) |
|---|---|
| доступно | усі вікна нижче `low` (60%) |
| мало | будь-яке вікно ≥ `low` |
| резерв | тижневе ≥ `weeklyReserve` (75%) |
| вичерпано | вікно ≥ `exhausted` (90%) або свіжий реактивний сигнал про ліміт |
| невідомо | даних немає або вони старші за `limits.staleAfterMin` (30 хв) |

Вікно, час скидання якого вже минув, вважається порожнім (0%). Для `agy` відсотки беруться з групи моделей із найменшим використанням (агент доступний, поки є хоча б одна група з запасом); вибір моделі з потрібної групи зробить роутер на Етапі 4.

## Дані й приватність

Стан лежить у `~/.switchboard/` (права `0600`, поза git). Email показується замаскованим (`ole…@gmail.com`), токени в логи не потрапляють (`packages/core/mask.ts`).

## Дешборд

Astro SSR (`apps/dashboard`), слухає **лише `127.0.0.1`**, у Netlify не деплоїться.

- Шапка: чипи `N доступно · N мало · N резерв · N вичерпано · N невідомо`, час оновлення, кнопка «Оновити».
- Картка агента: статус (завжди текстом, не лише кольором), смуги «5 год» і «Тиждень» із `aria-valuenow`, відлік `↻ 3 г 36 хв`, для `agy` ще групи моделей, нижній рядок з кількістю моделей, джерелом і віком даних. Дані старші за 30 хв напівпрозорі з позначкою «застаріло»; вичерпаний агент має пунктирну рамку.
- Ручні картки (Gemini-чат, Stitch): кнопки «Доступно» / «Вичерпано». У роутингу участі не беруть; список у `dashboard.manualCards` конфігу (`[]` ховає їх).
- Сторінка кожні 30 с запитує `/fragment` (готовий серверний HTML) і підміняє `#dashboard`; відліки й «2 хв тому» перераховуються в браузері кожні 15 с. Сервер перечитує ліміти з CLI не частіше ніж раз на `dashboard.refreshTtlSec` (60 с); кнопка «Оновити» читає одразу.
- `/api/status` віддає те саме у JSON; `POST /api/refresh` і `POST /api/manual` змінюють стан. Усі запити з чужим `Host` (DNS-rebinding) або чужим `Origin` дістають 403.

### Як перефарбувати

Усі кольори, радіуси й відступи — це CSS-змінні на початку `apps/dashboard/src/styles/global.css`. Розмітка карток: `apps/dashboard/src/components/`.

## Запуск задачі (`sb run`)

1. Перевіряє, що папка є git-репозиторієм і **робоче дерево чисте** (інакше зупиняється з кодом 3 і нічого не чіпає).
2. Створює гілку `sb/<id>` від поточної, пише `.sb/tasks/<id>.md` (тип, пріоритет, Figma, критерії готовності).
3. Запускає агента без інтерактивності (`claude -p …` або `agy -p …`) у корені проєкту. Дозволи беруться з секції `permissions` у `switchboard.config.yaml`; повного обходу підтверджень немає. Тайм-аут за замовчуванням 20 хв, при перевищенні вбивається вся група процесів.
4. Лог іде в `~/.switchboard/runs/<run-id>.log` з маскуванням токенів і ключів; сам промпт у лог не пишеться.
5. Результат оцінюється **не за кодом виходу**, а за відповіддю агента: заблоковані дії (`permission_denials` / `denied_actions`) дають статус «заблоковано», `is_error` або тайм-аут дають «помилка». Враховується і власна оцінка агента в `PROGRESS.md`: `Status: blocked` дає «заблоковано» (з першим відкритим питанням як причиною), `Status: in-progress` дає «не завершено» (чекає продовження).
6. Завершена задача: коміт `feat(sb): … [<id>]`. Інакше (помилка, заблоковано, не завершено): чекпойнт `wip(sb): checkpoint <id> from <agent>` (щоб не втратити зроблене). Порожніх комітів немає.
7. Проєкт повертається на гілку, з якої стартували. `main` не змінюється ніколи; push гілки лише з `git.pushBranches: true`, без `--force`; мерж і деплой робиш ти.

Коди виходу: `0` готово, `1` помилка, `2` неправильні аргументи, `3` брудне дерево, `4` заблоковано.

Типи задач і порядок агентів задаються в `routing` конфігу. Щоб додати тип, допиши рядок (`landing: [claude, agy]`) і, за бажання, критерії готовності для нього в `DONE_CRITERIA` у `packages/core/tasks.ts`.


### Запуск через `agy`: тимчасові права

`agy` у headless-режимі бере дозволи лише з **користувацького** `~/.gemini/antigravity-cli/settings.json` (перевірено розвідкою, `docs/recon.md`). Тому `sb run --agent agy`:

1. робить бекап цього файлу (`~/.switchboard/backups/`, лишаються 5 останніх) і додає правило `write_file(<повний шлях проєкту>/)`: запис дозволено лише всередині проєкту (вкладені папки теж), поза ним і в сусідніх папках заборонено;
2. після запуску знімає **саме ці** правила (оригінал повертається побайтово; якщо ти встиг змінити файл, лишаються твої зміни);
3. при збої, тайм-ауті, Ctrl+C чи `kill` теж знімає; після аварії наступний `sb run` дочищає сам (журнал `agy-rules-journal.json`); два запуски `agy` одночасно відхиляються.

Shell для `agy` **не вмикається** взагалі: `deny` у `agy` не зупиняє команди (`rm` пройшов). Задачі, яким потрібні `git`/`pnpm`, віддавай Claude. На час запуску те саме правило діє й у твоїх власних сесіях `agy` у цій папці.

### Захищені файли

Після кожного запуску (для будь-якого агента) перевіряється, чи не змінено файли з `git.protectedPaths` (за замовчуванням `netlify.toml`, `.env*`). Якщо змінено: задача «заблокована», гілка не пушиться, у виводі видно, що саме.

### Якщо перервати `sb run`

Робота агента зберігається в коміті `wip(sb): checkpoint <id> interrupted`, задача отримує статус «помилка (перервано)», проєкт лишається на гілці `sb/<id>`. Повернутися: `git switch <твоя-гілка>`.

## Роутер і передача між агентами (Етап 4)

`sb run` без `--agent` читає свіжі ліміти й обирає агента з `routing` (порядок = вподобання):

| Статус агента | Що він бере |
|---|---|
| доступно | будь-які задачі |
| мало | лише короткі типи (`router.shortTypes`: `section`, `copy`, `qa`) |
| резерв | лише `--priority high` |
| вичерпано | нічого до часу скидання |
| невідомо | бере, але спершу пробується агент з відомим статусом |

Для `review` рецензентом завжди стає **інший** агент, ніж автор коду: автор береться з історії задачі, яку рецензуєш (`--reviews <id>`). Якщо інший агент зараз зайнятий, рев'ю чекає, а не віддається автору. Коли вільних агентів нема, задача стає в чергу (`чекає`) до найближчого часу скидання, і приходить системне сповіщення.

**Як визначається ліміт.** Запуск вважається «впертим у ліміт», лише якщо він **завершився невдало** і один із патернів `limitDetection.patterns` збігається з **останніми** `tailLines` рядками виводу (текст, скопійований із самої задачі, ігнорується, тож слово «quota» у задачі нічого не запускає); або свіжий зріз використання показує вікно 100%. Тайм-аут і заблоковані дії ліміту не означають. Час скидання береться зі зрізу, а якщо його нема, з тексту повідомлення (`resets 3pm`, ISO, unix-час після `|`), інакше +1 година. Агент отримує позначку «вичерпано» до цього часу; якщо вона хибна, зніми її `sb unblock <агент>`.

**Що відбувається при ліміті:**
1. коміт `wip(sb): checkpoint <id> from <агент>`;
2. якщо агент не оновлював `PROGRESS.md`, дописується секція `Handoff` (змінені файли `git diff --stat`, останні ~40 рядків виводу без секретів, час, причина); якщо оновлював, його нотатки лишаються як є;
3. роутер обирає наступного агента, і той отримує промпт продовження («You are continuing a task started by another AI agent that hit its usage limit…»; для `agy` без `git`, бо в нього нема shell, замість цього він читає секцію Handoff);
4. не більше `handoff.maxHandoffs` (2) передач на запуск; далі пауза, статус `чекає`, сповіщення.

Опції: `--no-handoff` зупиняє задачу на першому ліміті, `--agent` закріплює першого агента (передача при ліміті все одно можлива).

**Як додати новий тип задачі в матрицю.** У `switchboard.config.yaml` допиши рядок у `routing`, наприклад `landing: [claude, agy]`; якщо тип короткий (бере навіть агент зі статусом «мало»), додай його ще й у `router.shortTypes`. За бажання додай критерії готовності типу в `DONE_CRITERIA` у `packages/core/tasks.ts`.

**Додати патерн ліміту.** Коли побачиш справжнє повідомлення про ліміт, допиши регулярний вираз у `limitDetection.patterns` (регістр не важливий). Перше справжнє повідомлення варто зберегти: Switchboard пише його в лог запуску `~/.switchboard/runs/<id>.log`.

Фонового планувальника немає: задачу з черги запускає `sb resume <id>` або `sb queue --run-due`.

## Панель задач на дешборді (Етап 5)

Під картками лімітів на `http://127.0.0.1:4321`:

- **Нова задача**: текст, тип (з матриці `routing`), проєкт (випадаючий список), пріоритет, посилання на Figma. Кнопка «Запустити» стартує окремий процес `sb run`, тож задача переживе перезапуск дешборду. Агента обирає роутер.
- **Виконується**: тип, проєкт, гілка, агент, тривалість, хвіст логу (останні 20 рядків), кнопка «Зупинити» (процес отримує SIGTERM: агент зупиняється, правила `agy` знімаються, робота зберігається чекпойнтом). Поки задача йде, сторінка оновлюється кожні 5 с (інакше 30 с). Claude віддає відповідь одним блоком наприкінці, тож під час роботи лог може бути майже порожнім.
- **Черга**: задачі, що чекають скидання ліміту, з очікуваним стартом і відліком; кнопка «Продовжити» (`sb resume`).
- **Історія передач**: `Claude Code → Antigravity о 14:32, причина: 5-год ліміт`, найновіші зверху.
- **Останні задачі** зі статусом (готово / заблоковано / помилка), гілкою і приміткою; для заблокованих і невдалих є «Продовжити».

### Безпека запуску з дешборду

- Проєкт обирається **лише зі списку дозволених**: `dashboard.projects` у конфігу, `sb project add <папка>` і проєкти з минулих `sb run`. Шлях звіряється за реальним (після `..` і symlink), інакше відмова.
- Текст задачі передається після `--`, тож текст на кшталт `--project /etc` ніколи не стає опцією; усі аргументи йдуть масивом, без shell. Figma-посилання має вести на `figma.com` (https), довжина тексту до 5000.
- Усі ендпоінти (`/api/tasks`, `/api/task-action`, …) відхиляють чужий `Host` (DNS-rebinding) і чужий `Origin` (403). Зупинка діє лише на процес, команда якого містить `bin/sb.ts`.
- У проєкті одночасно виконується одна задача (друга дістане відмову 409).
- Задача, процес якої зник (`kill -9`, вимкнення), сама позначається як «помилка» і її можна продовжити.
